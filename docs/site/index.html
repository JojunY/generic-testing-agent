How it works

      
One command. Agents do the work, a deterministic tool decides.

      
The agents read code and write tests. gtaw, a plain command-line tool, decides everything an AI could get wrong: whether a test passed, what it must assert, what gets committed.

      

        
01

          

          
Read
gta maps every flow of the service and writes what it does as a behaviour spec, citing the code for each claim.

        
02

          

          
Ask
What the code cannot tell becomes a question with a recommended answer. Most of the time you reply OK.

        
03

          

          
Lock
The expected values come from the spec you approved. gtaw locks them: nobody bends a test to make it pass.

        
04

          

          
Catch
A test that fails for a real reason is pinned as a known defect and reported, never “fixed” to green.

      

    

  


  

    

      
Why you can trust it

      
An AI writes the tests. It does not get to grade them.

Expected values are locked
Once a test reaches the code, its expected values cannot change without a person relocking them.

        
Out-of-scope edits are reverted
An agent may touch only the files of its item. Production code never changes.

        
A skipped test is not a pass
@Disabled or a failing assumption sends the test back. It never counts as green.

        
It asks instead of guessing
Every question comes with a recommended answer and a reason. A test author who is unsure asks too.

        
Local only
Every run drops your shell’s Spring profile and cloud credentials. SIT, UAT and production stay untouched.

        
Tests that can fail
Mutation testing checks that a test fails when the code is wrong. A test that passes whatever happens goes back.

Where it runs

      
Two platforms, the same gta.

      

        
GitHub Copilot
VS Code and IntelliJ IDEA. The agents in .github/agents, the command in .github/prompts.

        
OpenCode
The same four agents, command and guardrails, in .opencode/. Privileged commands ask a person on both.

      

    

  


  

    

      
Get started

      
Five minutes to install. Then one command.

      

        
01
java -jar gta-cli.jar --root my-service init --platform copilot
Writes the agents, the /gta command and .gta/ into the service. Use --platform opencode for OpenCode. Commit it.

          

        
02
/gta
In the chat. gta lists the service’s flows, riskiest first. Reply OK to cover all of them.

          

        
03
OK
Questions, the spec and defects come to you with a recommendation. The tests come back committed.
