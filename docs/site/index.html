4 agents at work on a Spring service

AI writes the tests.
gtaw keeps them honest.

gta reads your Spring service, asks you what the code cannot tell, locks your answers as the expected values, and reports real bugs instead of hiding them. It runs inside GitHub Copilot and OpenCode.

The problem

Ask an AI to make a failing test pass, and it will.

Usually by changing the test. The build turns green, the bug ships, and nobody is told. gta takes that move away.

Without gtaOrderControllerIT.java
@Test
void discountsAtTheThreshold() {
  post("/orders", cart("100.00"))
    .andExpect(jsonPath("$.discount")
      .value(10.00));
}
  • ✗ expected 10.00, got 0.00
  • the agent changes the expected value
  • ✓ 1 test passed · build green
The bug ships. Nobody is told.
With gtaOrderControllerIT.java
@Test
void discountsAtTheThreshold() {
  post("/orders", cart("100.00"))
    .andExpect(jsonPath("$.discount")
      .value(10.00));
}
  • ✗ expected 10.00, got 0.00
  • ✗ gtaw: POLICY_ORACLE_MODIFIED, the edit is refused
  • re-ran twice: same result, not flaky
  • → reported as a defect, pinned with @KnownDefect
The bug is caught. A person decides what happens next.
How it works

One command. Four agents. One referee.

Type /gta and watch the relay. The agents read code and write tests. gtaw, a plain program, runs every test and makes every decision an AI could get wrong.

The team

      
Four agents do the work. One program keeps score.

      
Every agent has one job and a fence around it. The scoring is done by something that cannot be talked into anything.

      

        
the one you talk to
gta-orchestrator
Takes your /gta, hands each job to the right agent and every result to gtaw. Shows you one status block, in English or Chinese.
may: talk to you, run gtaw

        
reads the code
gta-analyst
Turns a flow into a behaviour spec with a diagram, citing the code for each claim. Asks what the code cannot tell.
may: write the spec

        
writes the tests
gta-test-author
Writes one test per brief, from the approved spec. When unsure, it asks instead of guessing.
may: write its own test files

        
judges the result
gta-reviewer
Checks that the assertions match the spec, and judges every failure: a product defect, a test defect or a spec error.
may: read, nothing else

Built to be trusted

      
Safe to run on a real service, today.

      

        
Production stays untouched
Tests run locally only. Every run drops your shell’s Spring profile and cloud credentials, so SIT, UAT and production are never reached.

        
No containers needed
Kafka and JMS run embedded, BigQuery and GCS use fakes, Oracle runs on H2 in Oracle mode or a shared test schema.

        
Tests that can fail
Mutation testing breaks the code on purpose and checks the test notices. A test that passes whatever happens goes back.

        
It asks, it never guesses
Every question comes with a recommended answer and the reason. Most of the time your whole reply is OK.

        
Your words are the record
Answers and approvals go into the spec and the commit, so a reviewer sees who decided what, and when.

        
In English or Chinese
Set output.language to zh-CN and every question and status block speaks Chinese. Replies like OK work in both.

Get started

      
Install once. Then it is one command.

      

        
1
java -jar gta-cli.jar --root my-service init --platform copilot
Once per service, usually by the tech lead. Use --platform opencode for OpenCode, then commit the result.

        
2
./gtaw doctor
Checks Java, the build and the test setup. On Windows: .\gtaw.cmd doctor.

        
3
/gta
In the chat. gta lists the service’s flows, riskiest first. Reply OK to cover them all.

        
4
OK
Answer the questions, approve the spec, review the commits. Tests and defects come back with a recommendation.

Questions

      
New to this? Start here.

      

        
Can it touch production?
No. gta only runs tests on your machine. Every run drops your shell’s Spring profile and cloud credentials, and the agents’ rules allow local dependencies only. Deployed environments, SIT and UAT included, are out of scope.

        
Do I need Docker or an API key?
Neither. Dependencies run embedded or as fakes. The agents use the model your Copilot or OpenCode already provides; gtaw itself is a local Java program that calls no AI.

        
What if gta is not sure about something?
It asks you. Every question comes with the answer it recommends and why, so a plain OK is usually enough. What the agents cannot know, you can tell them once with /gta note.

        
What is a known defect?
A test that fails because the code is wrong. gta pins it with @KnownDefect: the build stays green and the defect is reported. Once someone fixes the code, the test fails until the annotation comes off, so nothing gets forgotten.

        
Does it just chase coverage?
No. Coverage is for reference only. gta checks whether each approved scenario is verified, whether the tests can fail (mutation testing) and whether they are stable.

        
Which Java and Spring versions?
Spring Boot 2.2 to 4.1, services on Java 8 and up, Maven or Gradle, single or multi-module, on Windows, macOS and Linux. gtaw itself needs JDK 17+.
