The cast

Four agents. One job each.

gtaw is not a fifth agent. It is the referee: a deterministic Java program. The same input produces the same decision, and it calls no model.

01 · The one you talk to

gta-orchestrator

Takes /gta, asks gtaw for the next node, and hands it to the analyst, the author or the reviewer. It shows gtaw’s status block. It does not write the spec or the test, and it never answers for you.

next, check, submit, answer, note, statusno file editsno git, no mvn
02 · Reads the code

gta-analyst

Turns one flow into a behaviour spec: requirements, scenarios, a diagram, and a question wherever the code is not enough. It describes. It does not decide that today’s behaviour is correct.

writes the named speccannot mark source=confirmed
03 · Writes one test

gta-test-author

Writes the test for one approved scenario. Expected values come from the locked spec. When the spec and the code do not settle how to write it, the author asks instead of guessing.

test files in the briefno src/mainno @Disabled
04 · Judges, and does not edit

gta-reviewer

Reads the test against the approved scenario and returns one verdict. It never recommends changing the expected value to whatever the code returned.

read onlyone verdict

Tests run on this machine
gtaw and the tests run on your machine. A model request, and how that data is handled, depends on GitHub Copilot or OpenCode and on the provider you use. Each test run drops cloud credentials and the shell’s Spring profile and config variables. SIT, UAT and production are out of scope. The agents’ rules allow local dependencies only. Kafka and JMS run embedded. BigQuery and GCS use fakes. Oracle uses H2 in Oracle mode or a shared test schema. Pub/Sub uses an in-memory fake or an emulator.

          
It asks. It does not guess.
A bare OK takes the recommendation. OK, 2B changes one option. 好 and 确认 count as OK. 批准 order.create@R2 approves that revision. 其余默认 keeps today’s behaviour for the rest; those scenarios become characterization tests. They lock what the code does now. They do not prove it is right.

          
A known defect stays visible
A test that fails because the code is wrong can be pinned with @KnownDefect. The build stays green while the defect exists. After the code is fixed, the test turns red until the pin is removed. Coverage is reference only.

          
Versions
Spring Boot 2.2 to 4.1. Services on Java 8 and up. Maven or Gradle, one module or many, on Windows, macOS and Linux. gtaw itself needs JDK 17 or newer. No separate model key: the agents use the model Copilot or OpenCode already provides. A model request, and how that data is handled, depends on that product and on the provider you use. gtaw calls no model, and it does not need Docker.

        

      

    


    

      

        
Install

        
Build it once. Then the command is /gta.

        
From this repository the jar is the one you just built. A published jar also needs --distribution-url and --distribution-sha256. gtaw will not download an unpinned jar. The full notes are in the quickstart and the design.

              mvn -B install
              
    In this repository. Builds gtaw and runs its tests.

  2. 
            
    
              java -jar toolkit/gta-cli/target/gta-cli.jar --root my-service init --platform copilot
              
    Once per service, usually by the person who owns the build. Use --platform opencode for OpenCode, then commit what init wrote. For a jar from Nexus, add the URL and the sha256 from the quickstart. For local development, GTA_CLI_JAR points gtaw at the jar you built.

    Checks the JDK, the build and the harness. On Windows: .\gtaw.cmd doctor.
