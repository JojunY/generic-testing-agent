gta · generic testing agent · for Java services built with Spring

AI writes the tests.
It doesn’t get to grade them.

A model writes regression and integration tests for your service. gtaw, a deterministic referee with no model inside, runs them, checks them against expectations a person approved, and locks those. Nothing on this board turns green before gtaw has the evidence.

01 · The problem

Green is not proof.

A model that writes a test and also decides whether the test is right will bend the test until it is green. One method of the lending sample is enough to show it. When the inventory service does not answer, the fallback says the shares are reserved:

// InventoryClient.java
Reservation inventoryDown(String security, long quantity, Throwable cause) {
    return new Reservation(true);
}

The model grades itself

It asserts what the code does.

It reads the method, writes a test that expects a booked borrow, runs it and reports success.

assertThat(response).hasStatus(201);

Green. The defect now has a test that protects it.

Illustration of a self-graded test for this method.

gta

It asserts what a person signed.

The analyst sees that docs/business-rules.md disagrees with the code and asks. A person replies OK to the recommended answer. gtaw runs the test, gets expected: 503 but was: 201, re-runs it, has it triaged and asks the person once more.

assertThat(response).hasStatus(503);

The build stays green. The defect stays visible.

02 · The one idea

Three hands. One job each.

Banks call it maker and checker: whoever makes an entry is never the one who approves it. gta applies it to tests.

The agents

Write

analyst · test author · reviewer

  • read the code
  • write the spec, with questions and a recommended answer
  • write one test per brief
  • give a verdict on a test or a failure

Never

  • decide that a test passed
  • change state or commit
  • touch production code

gtaw

Decides

a Java CLI · no model inside

  • plans the items from the approved spec
  • runs the tests
  • checks that the spec’s expected values are asserted, and locks them
  • restores edits outside an item’s files
  • commits, and runs the gate

Never

  • guesses: what it cannot decide goes to a person

You

Sign

developer · product owner

  • answer the questions, usually with OK
  • approve the spec
  • confirm a defect

Never have to

  • read every test: the spec is what you sign

05 · Limits

Where it does not go.

  • No deployed environment. Tests run on a developer machine or in CI, against embedded or faked dependencies. There is no mode that targets SIT, UAT or production.
  • No borrowed identity. gtaw starts every test run with cloud credentials cut off and with your Spring profile removed: a shell set to UAT cannot make a test load UAT’s configuration.
  • No production code. An edit outside the files of an item is restored. A defect is pinned and reported, never patched.

Where this stands

Proven

The referee. gtaw has unit tests with a 90 % line coverage gate and six scripted end-to-end runs, in which a script plays the agents. The 21 seeded defects of the four sample services are found and pinned.

Not proven yet

The players. No run with a real model on a real service is recorded in this repository. Treat every capability as unproven with models until its pilot is done.

06 · Start

One script, then /gta.

The script builds gta once, installs it into your service with the wrapper pinned to that jar, and runs ./gtaw doctor. Then open the service in VS Code, IntelliJ or OpenCode.

    In a checkout of this repository

    scripts/install-local.sh path/to/your-service
  2. 2

    In GitHub Copilot or OpenCode, inside your service
