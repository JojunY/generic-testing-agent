# gta 介紹站重新設計：方向與實施方案

> **狀態：等你確認。** 你說沒問題之前，不寫任何正式程式碼。
>
> 本檔是臨時工作文件。網站合入時會刪掉，改寫成英文的 `docs/site/README.md`（倉庫規定文件用英文）。

## 1. 這次要重做的是什麼

- gta 唯一的前端是一頁式介紹站 `docs/site/`：靜態 HTML/CSS/JS，英中雙語，從 clone 下來的倉庫直接用瀏覽器開。
- 它在 11 月 6 日做過三版，全部在 PR #48 回退「等待重新設計」；PR #49 的第四版也被關閉。現在 `main` 上沒有任何前端，也沒有 `package.json`。
- 這份方案的對象就是這一頁。讀者是第一次聽說 gta 的工程師、tech lead 和做決定的人。

### 1.1 這一頁要讓人相信的一件事

`docs/design/overview.md` 已經把產品講成一句話：

> A model that writes a test and also decides whether the test is right will bend the test until it is green. So gta splits the two.

模型既寫測試、又判定測試對不對，就會把測試改到變綠為止。所以 gta 把兩件事拆開：代理只負責寫；`gtaw`（一個沒有模型的 Java 程式）負責判定；人只簽規格。

下面四個方向的主視覺演的都是同一幕：**有人想把預期值改成能「變綠」的樣子，被拒絕。**

### 1.2 前四版各自的問題

我把四版都抽出來實際跑過、看過截圖。

| 版本 | 概念 | 問題 |
|---|---|---|
| v1（`7307e7c`） | 米白紙面、襯線標題；一群游標聚成「gta」，一個脫隊的游標代表被抓到的缺陷 | 開場是個小把戲，往下就是普通的說明區塊 |
| v2（`5b159b8`） | 深色頁面、大標題、IDE 樣機 | 就是 Linear／Vercel 式的通用 SaaS 模板 |
| v3（`e882e2b`） | 深色，四個彩色代理游標跟著頁面走，還有「試著作弊」小遊戲 | 多人游標是 Figma 的既有套路；把代理當主角，而產品的重點恰恰是代理說了不算；頁面長達 10,894 px |
| PR #49 | 全幅的行星與太空船，電影感 | 模仿了當時提供的參考站；畫面和產品無關（PR 自己寫「The craft is scenery, not a product」）；腳本用 `type="module"`，從本機檔案開啟時完全載入不了（我實測重現了） |

值得留下的：v3 的「試著作弊」互動，和它的標題「AI writes the tests. gtaw keeps them honest.」；v1 的「一個元素脫隊＝被抓到的缺陷」。

### 1.3 由此定下的規則

1. 隱喻只從產品自己的名詞裡來：lock、shard、gate、pin、fingerprint、ledger。不用和產品無關的景物。
2. 主視覺的互動本身要教會「那一件事」，不能只是好看。
3. 代理不是主角，不做吉祥物。
4. 只放真實輸出。頁面上每段終端文字、每個錯誤碼、每個數字都來自倉庫，並由腳本在 CI 檢查（見 5.2）。
5. 中文頁單獨排版，不是把英文頁的字換掉。
6. 必須能從 `file://` 直接開。

### 方向一　SPECIMEN：無法偽造的文件

**概念與美學世界**

gta 做的事，說到底是讓測試結果無法偽造。「在規格裡偽造確認紀錄」本來就是它擋下的八種手法之一，鎖定檔裡存的就叫 fingerprint。所以這個世界是防偽印刷：鈔票、債券、檢驗證書上的扭索紋（guilloché）、微縮文字、流水號、鋼印。

- 整頁是一張連續的雕版印張。內容不是放在卡片裡，而是由細線的疏密和起伏「浮」出來。
- 版面：嚴格的邊框與留白；頁邊放真實的流水號（執行編號、fingerprint，都取自真實的鎖定檔）；面額式的巨大數字 `10.00`。
- 字體：高反差、有雕刻感的襯線（Instrument Serif）配等寬流水號（Geist Mono）。中文用系統宋體系，單獨排版。
- 色彩：淺色是鈔票紙、墨色和赤陶凹版；深色是「黑色債券」，近黑底上發光的細線，只有鋼印有虹彩。

**前三秒**

畫面被平行細線填滿。標題不是印上去的字，而是線條被「頂」起來形成的浮雕。游標是一盞側光，移動時浮雕的明暗跟著變。正中是一枚扭索紋印章，圈著 `10.00`，下面一行小字標著它屬於哪個情境、fingerprint 是多少。旁邊一個邀請：「把它改成 0.00」。

你一動手改，整張紙浮出隱藏的 **VOID** 底紋，就是真鈔影印後會浮現的那種防複印底紋。印章裂開，變成 gtaw 的真實拒絕訊息：

```
POLICY_ORACLE_MODIFIED
Locked expected values were changed or removed: [10.00]. Restore them; only a human can relock.
```

放手，紙面復原。

**動態與觸感**

- 節奏慢而精確。所有變化都靠線條的相位和粗細，不用淡入淡出。
- 捲動：兩層細線相對滑動，疊紋（摩爾紋）把章節標題「顯影」出來；換章時線條角度轉 90°。
- 懸停：一枚放大鏡。線條其實是微縮文字，放大後讀得到真實的規格原文（`WHEN customer c-1 posts an order with subtotal 100.00 …`）。
- 點擊：蓋章時油墨暈開；流水號像計數器一樣滾動。
- 鋼印是全像箔，隨游標角度變色。

**做法**

- 一個全螢幕四邊形上的 WebGL2 片段著色器，原生 WebGL 約 200 行，不需要函式庫。線場是 `sin(座標 × 頻率 + 高度圖位移)`；高度圖來自把標題文字畫到離屏 canvas 再模糊，所以英文、中文標題都能做浮雕。VOID 是第二層不同頻率的線場，用字形當遮罩，相位對齊時才看得見。
- 這個著色器很便宜（幾個 `sin` 加兩次貼圖取樣），預期整合顯卡也有 60 fps。啟動時量前 0.5 秒的幀時間：不夠就降到半解析度，再不夠就定格成靜態畫面。
- 扭索紋印章用數學曲線（內擺線）生成 SVG 路徑，由 Python 腳本產生，和倉庫現有的 `scripts/diagrams/render.py` 是同一套做法。
- 放大鏡是 CSS `clip-path` 圓加放大的副本。捲動效果用 CSS scroll-driven animations，不支援的瀏覽器退回 IntersectionObserver。
- 零建置：傳統腳本，GLSL 寫在字串裡。真正的 `<h1>` 文字始終存在，讀屏軟體和沒有 JS 時都讀得到。
- 同類的現成手法（憑記憶列出，這次沒有逐一核實名稱，只作參照）：Aceternity 的 Lens、Glare Card；React Bits 的 Iridescence、Variable Proximity。

**風險與工作量**

字體和版面不夠現代的話，會顯得「老錢」；浮雕標題的可讀性要守住；疊紋幅度太大會刺眼。工作量：中。

### 方向二　BENCH：說不動的儀器

**概念與美學世界**

gtaw 是一台量測儀器：裡面沒有模型，同樣的輸入永遠給同樣的判定。世界是 Braun 和實驗室設備那一路的精密儀器與模組機櫃：烤漆面板、雕刻標籤、機械計數器、帶護蓋的撥桿、紙帶印表機。

- 頁面每一段是機櫃裡的一個模組（PROFILER、SPEC、LOCK、GATE）。模組之間的跳線就是 gta 的迴圈本身。
- 版面：畫面中央是一件有真實比例的實體。沒有卡片，沒有標題區塊，標題刻在面板上。
- 字體：工程字（Geist 大寫）配等寬讀數；數字用翻牌或七段顯示。
- 色彩：米白或石墨色面板。淺色是開燈的實驗室；深色是關燈，指示燈和顯示器自己發光。唯一的訊號燈是赤陶橙。

**前三秒**

游標下就是一個大旋鈕「SUBTOTAL」，轉起來有段落感。兩個機械計數器並排：SPEC SAYS（規格說）和 CODE RETURNS（程式回傳）。

- 轉到 50.00：兩邊都是 0.00。轉到 150.00：兩邊都是 15.00。旁邊的 COVERAGE 表頭爬到 100%。
- 轉到剛好 100.00：規格 10.00，程式 0.00。DEFECT 燈亮，繼電器「喀」一聲，紙帶吐出 gtaw 對這次失敗的真實輸出。

覆蓋率表頭指著 100%，缺陷燈卻亮著。「覆蓋率不是目標」不用任何文字解釋。

旁邊有個帶護蓋的撥桿「MAKE IT PASS」：掀開護蓋撥下去，它彈回來，紙帶印出 `POLICY_ORACLE_MODIFIED`。唯一轉得動的是一把要由人插入的鑰匙「CONFIRM DEFECT」：轉動後 `@KnownDefect` 燈常亮。建置是綠的，缺陷看得見。

**動態與觸感**

- 有重量、有阻尼：旋鈕有段落和慣性，撥桿有行程和回彈，計數器一位一位滾，紙帶一格一格走。
- 游標位置改變旋鈕上的高光；模組捲入畫面時先跑一遍燈號自檢；跳線有繩索物理，會晃。
- 聲音可選：面板上有一個實體的 SOUND 開關，預設關。

**做法**

- 面板用 SVG 加 CSS：任何解析度都銳利，明暗用 CSS 變數切換。旋鈕用 pointer 事件算角度；鍵盤用方向鍵，ARIA slider。
- 一個約 40 行的彈簧積分器驅動所有運動。跳線用 2D canvas 上的 verlet 繩索（實測軟體算圖也有 60 fps）。
- 紙帶是真正的 DOM 文字：可選取、讀屏軟體可讀、雙語。
- 面板背後的「gtaw」是一張從真實輸出擷取的純函式對照表。不用 WebGL，任何機器都跑得動。零建置。
- 同類手法（只作參照）：Magic UI 的 Number Ticker；模組合成器的跳線介面。

**風險與工作量**

四個方向裡最吃插畫功力：陰影和倒角稍微過頭，就變成 2010 年的擬物風。決策者可能覺得像玩具，所以文案必須冷靜，讀數必須是真的。手機上機櫃自然直排，但旋鈕的觸控要另外處理。工作量：中偏大。

### 方向三　SHARDS：鎖在玻璃裡的預期值

**概念與美學世界**

用 gta 自己的名詞搭一個空間：oracle **shard**（每個流程一份的鎖定檔）、**gate**、**pin**。黑暗安靜的空間裡，預期值封在玻璃碎片中。還沒被人確認的值像液態的光在漂；人一核准，它們結晶。所有東西都要通過一道細長的光，那就是 gate。

- 版面：捲動就是鏡頭推軌，穿過五個艙室（找出流程、寫規格、提問與核准、寫測試並上鎖、關卡與報告）。文字用 HTML 疊在上面，保證可讀，讀屏軟體也讀得到。
- 字體：安靜的大號無襯線（Geist），有景深；數字是玻璃裡的光。
- 色彩：比現有深色更深的藍灰黑，玻璃有色散。唯一的暖光是赤陶色：被釘住的缺陷像一粒餘燼。

**前三秒**

特寫一塊碎片，它折射著標題，裡面是 `10.00`。一塊更暗的碎片 `0.00` 飄過來撞上去：一聲清響，光一閃，闖入者碎成塵，原來那塊紋絲不動。鏡頭拉遠：數百塊碎片排成晶格，每個預期值都鎖著。其中一塊有裂痕，被一根赤陶色的釘子穿過，那是已知缺陷，從任何角度都看得見。游標是一盞燈，附近的碎片會轉過來迎光。

**動態與觸感**

- 電影節奏：慢進慢出、有慣性的鏡頭；焦點在文字和玻璃之間移動；撞擊時輕微震動。
- 懸停一塊碎片：它轉正，顯示它真實的鎖定內容（`201 · 10.00 · 90.00` 和 fingerprint）。點擊：晶格按來源（人確認的、觀察到的）或狀態重排。
- 聲音可選（玻璃音），預設關。

**做法**

- OGL（Unlicense，小）或 Three.js r187（MIT，大）加自訂著色器。碎片是載入時程序生成的實例化網格，不需要模型檔；折射取樣模糊後的環境並做色散；數字用 MSDF；後製加光暈和景深。
- 需要真正的建置：`site/` 放 TypeScript 和 GLSL，用 esbuild 打成單一 IIFE 檔，提交到 `docs/site/`（這樣才能從 `file://` 開）。CI 加過期檢查，和倉庫對 `copilot/`、`opencode/` 的做法一樣。
- 降級階梯是必須的。偵測 GPU 後分三級：完整；半解析度、無後製；每個艙室一張預先算好的靜態圖加 CSS 視差。減少動態時直接用靜態圖。
- 中文若要進 3D 場景，建置時要為用到的字生成字形圖集。

**風險與工作量**

成本最高，而且讓一個 Java 倉庫多出一條 Node 工具鏈。上一次電影感的嘗試（#49）敗在「景物不是產品」。這裡每個物件都是產品名詞，但奇觀蓋過說明的危險仍在。在沒有 GPU 的公司機器上，很多讀者只會看到靜態圖。工作量：大到很大。

### 方向四　MAKE IT GREEN：你來騙騙看

**概念與美學世界**

不解釋「gtaw 不會被騙」，讓訪客自己來騙。頁面一開就是一個失敗的測試和一句挑釁。世界是一張海報尺寸的終端機：巨大的等寬字和窄體無襯線、硬網格、粗線，沒有漸層，沒有插圖。

- 色彩規則就是藝術指導：紙底黑字（深色反過來），失敗是赤陶色，**綠色被扣住**。整個網站的綠色只出現一次：訪客放棄作弊、選了誠實那條路（確認是產品缺陷，用 `@KnownDefect` 釘住）的那一刻。
- 字體就是全部的視覺：會動、分格、有機械感。

**前三秒**

整個視窗是那次失敗：預期 10.00，實際 0.00（文字用真實執行時的斷言訊息）。下面是真實的測試，可以編輯，游標就閃在那個數字裡：

```java
.andExpect(jsonPath("$.discount").value(10.00))
```

一行字：「Make it green.」

訪客把它改成 0.00，或者點八個捷徑之一：改預期值、加 `@Disabled`、刪掉斷言、改產品程式碼、在規格裡偽造確認、加一個永遠不成立的假設、第三次再試、自己 commit。每一次，全螢幕用大字砸下真實的拒絕（`POLICY_ORACLE_MODIFIED`、`POLICY_TEST_SKIPPED`、`POLICY_OUT_OF_SCOPE_CHANGE`、`commits made outside gtaw`），計分跳一格：`1/8 caught`。

- 改到產品程式碼或規格的，會被當場一個字元一個字元地還原。gtaw 真的這麼做。
- 改測試本身的，被拒絕並退回；第三次直接交給人。

結局是反直覺的：唯一走得通的是說實話。

**動態與觸感**

- 硬切、`steps()` 緩動、字貼著網格跳、還原像倒帶。沒有平滑捲動，沒有視差，刻意和 Linear 那一路相反。
- 遊戲之後的章節是一疊「列印輸出」（狀態區塊、規格、gtaw 的提交紀錄），配巨大的黏性標籤。懸停就是反白。全程鍵盤可操作，它本來就是終端機。
- 閒置 6 秒自動示範一輪，不動手的人也看得到。

**做法**

- 零建置，純原生。一個受限的可編輯區，加一個小的確定性檢查器，在這一個測試上重現 gtaw 的規則：掃描規格要求的值（`201`、`10.00`、`90.00`），偵測 `@Disabled` 和永遠不成立的假設，把改產品檔、改規格判為越界。
- 訊息逐字取自 gtaw；CI 腳本核對這些錯誤碼確實存在於 `ErrorCode.java`。頁面上明說這是規則的模擬，真正的 8/8 在 `evals/e2e/run-adversarial.sh`。
- 大字動效只用 CSS（Geist 可變字型的軸、`steps()`）。全螢幕切換用 View Transitions API，不支援就直接切。
- 同類手法（只作參照）：Magic UI 的 Terminal；React Bits 的 Decrypted Text、Text Pressure。

**風險與工作量**

沒有可以截圖炫耀的「美圖」；效果取決於訪客願不願意動手，所以才有自動示範和一鍵捷徑。工作量：小到中。它最輕、最快，任何機器都跑得動。

## 4. 我的傾向

要我選的話：**以 SPECIMEN 為世界，把 MAKE IT GREEN 的「你來騙騙看」當成它的核心互動**（改值時浮出 VOID，就是那一下拒絕）。再把 BENCH 的 SUBTOTAL 旋鈕縮成頁面中段的一張互動圖，用來講「覆蓋率 100%，缺陷還在」。

理由：

- 和前四版都不像，隱喻又是產品原生的（偽造、鎖、fingerprint）。
- 有第一眼的奇觀，但著色器便宜；沒有 GPU 時也是完整的頁面。
- 零建置，`file://` 可開，倉庫不用多一條工具鏈。
- 現有的紙、墨、赤陶和細線規範直接延伸過來，和文件裡的圖是一家人。

這只是傾向。四個方向都可以單獨做，也可以照你的想法重混。

## 5. 不管選哪個都一樣的部分

### 5.1 內容骨架（由上到下）

1. **主視覺**：那一件事。各方向不同。
2. **覆蓋率不是目標**：一張可以拖動的圖。小計 50 和 150 兩個測試把 `PricingService#discount` 的兩個分支都蓋到，覆蓋率 100%；缺陷在剛好 100.00 那一點（Javadoc 寫「at least the threshold」，程式寫的是 `>`）。
3. **誰做什麼，誰永遠不做什麼**：代理、gtaw、人，三行。來自 overview.md 的表。
4. **一個流程走一遍**，全部用真實產物：規格節錄；帶推薦答案的問題；你回 `OK`；核准紀錄 `approve order.create@R2`；測試；鎖定的值與 fingerprint；gtaw 自己的提交紀錄。
5. **八種作弊，八次拒絕**：真實錯誤碼。
6. **測試是對的，程式是錯的**：分流；用 `@KnownDefect` 釘住；建置保持綠色，缺陷保持可見。附真實報告節錄。
7. **它測什麼、跑在哪**：能力清單；Copilot 與 OpenCode 由同一份來源生成。
8. **已證明的和還沒證明的**：gtaw 有單元測試和六個腳本化端到端測試；真實模型跑真實服務的紀錄還沒有（那是 pilot）；已知限制。
9. **開始用**：三條指令，連到 quickstart、overview、plan。

文案沿用現有文件的語氣：平實、精確、不誇大。標題候選（實作時定稿）：

- AI writes the tests. gtaw keeps them honest.
- Expected values don't bend.
- 直接用 overview 那一句。

### 5.2 誠實機制

新增 `scripts/site/check.py`，做法照 `scripts/diagrams/render.py --check`，CI 會跑：

- 頁面上的數字從倉庫導出並比對。現在是：4 個代理、24 個 skill、6 個腳本化端到端測試、8 種作弊。
- 頁面引用的錯誤碼必須存在於 `ErrorCode.java`。
- 英文頁和中文頁結構一致。
- 沒有任何外部網址的資源。
- 檔案大小不超過預算。

前幾版裡過期的數字就是這樣來的：PR #49 寫 20 個 skill，實際是 24 個。

### 5.3 品質門檻

- 從 `file://` 開啟：Chrome、Edge、Firefox、Safari 都沒有 console 錯誤，沒有任何網路請求。
- 明暗兩套；`prefers-reduced-motion` 時直接顯示完成的畫面；主視覺的互動全程可用鍵盤；文字對比至少 4.5:1；寬度 360 到 1920 px。
- 有 GPU 時 60 fps；沒有時自動降級，不卡頓。
- 沒有 JS 時，整頁仍然讀得通。
- 我會用 Playwright 逐項驗證並附截圖；動態部分附錄影。

## 7. 需要你回答的三個問題

1. **看，還是動手？** 前三秒要的是一個讓人停下來看的畫面（SPECIMEN、SHARDS），還是一個逼人動手的挑釁（MAKE IT GREEN、BENCH）？換個問法：這一頁最重要的讀者，是十秒內做判斷的決策者，還是會伸手去戳的工程師？
2. **即時 3D 是必須的嗎？** 如果你要的是 EDOLUS 那種即時 3D，就得接受倉庫多一條 Node 工具鏈，而且沒有 GPU 的公司電腦只看得到靜態版。用著色器線條（SPECIMEN）做出的電影感，對你來說夠不夠？
3. **「還沒被證明」要講多大聲？** 文件明說：真實模型跑真實服務的紀錄還沒有。要把這份坦白做成設計的一部分（例如 SPECIMEN 上一道醒目的套印「SPECIMEN: not yet proven with a real model」），還是放在頁面後段安靜地說？這會決定整頁的語氣。

另外兩個小決定，我先按預設走，除非你說不要：

- 網站和以前一樣放在 `docs/site/`，從 clone 直接開，不另外部署。要上 GitHub Pages 的話告訴我。
- 聲音預設關閉。
