# gta 介紹網站重新設計：四個方向與實施計畫（待你確認）

> **狀態：等你確認。** 還沒有寫任何網站程式碼，也沒有沿用之前任何一版 UI 的概念、版面或素材。
> 這是工作文件，只放在工作分支上，不會進 main；開始實作時由網站本身取代。檔名帶 `.zh-CN` 只是為了通過倉庫的語言規則。

## 1. 你需要決定的事

最後一節有三個問題，每題都附推薦答案。回「OK」就是全部照推薦做：

- 以 **B · SOLARI（機械翻牌的判定看板）** 為主；
- 從 A 借一個互動：期望值可以試著改，但改不動；
- 以「你主講、大螢幕展示」為第一優先。

## 2. 我對這個專案的理解

brief 裡的 Project Seed 是空的，我依專案內容補上，請確認：

> **AI 可以寫考卷，但不能自己改分數。**
>
> gta 讓 AI 為 Spring Java 服務寫 spec 和測試。但測試過不過，由一個不含模型的程式 `gtaw` 判定；期望值由人批准後鎖住，AI 改不了；測試失敗時不是把測試改到通過，而是把缺陷釘出來。
>
> 關鍵詞：經辦與覆核分離（maker–checker）、證據、鎖、綠燈不等於正確、只要會打 `/gta` 和 `OK`。
>
> 想傳達的感覺：冷靜、可信、像機械一樣確定，帶一點「AI 想作弊被擋下」的幽默。

**範圍**：gta 本身沒有畫面，它活在 IDE 的聊天視窗裡。所以這裡的「UI 前端」指的是介紹網站加可以互動的 demo，不是產品內的儀表板。如果你要的其實是後者，請告訴我。

**三種讀者，各帶走一件事**：

| 讀者 | 要帶走的一件事 |
|---|---|
| 比賽評審 | 這個點子新在哪：把「寫測試」和「判定測試」拆給不同的角色 |
| 客戶、主管 | 為什麼可以信：有人簽核、每個通過都有證據、不碰部署環境 |
| 要上手的新人 | 我只需要會打 `/gta` 和 `OK` |

## 3. 工作區盤點：哪些事實限制了設計

- **沒有前端工具鏈。** 倉庫是 Java/Maven 專案，沒有 `package.json`。容器裡有 Node 22、Playwright 和 Chromium，可以用來截圖和驗證互動。
- **main 上沒有網站。** 之前的 `docs/site/` 不在 main 上，這次也不參考它。
- **倉庫測試對檔案有要求。** `RepositoryHarnessTest` 會掃描整個目錄的 `.md`、`.json` 等文字檔，出現中文就失敗；`.html`、`.js`、`.css` 不在掃描範圍。兩個後果：
  - 中文文案放在 `index.zh-CN.html` 裡；
  - 如果把 `node_modules` 放進倉庫，測試會失敗，也會變慢。
- **沒有接任何設計類的 MCP。** 目前只接了 Claude Academy；目錄裡有 Figma，但沒安裝。所以 React Bits、21st.dev、Magic UI、Aceternity 的互動模式只當參考，用原生程式重寫，不安裝它們。
- **對標網站。** EDOLUS 在 Awwwards 上的介紹是「a cinematic WebGL journey into AI infrastructure」，我把它理解成「電影感的質感」這條線。ScrollHaus 我查不到公開資料，所以沒有引用它的具體元件。
- **現有文件已有一套圖表風格**：紙、墨、單一強調色（`docs/guides/diagram-style.md`）。網站可以另立視覺；方向 A 剛好和它一脈相承。
- **你們的環境管制嚴**（依賴走 Nexus、Windows 機器）。所以網站要能雙擊 `index.html` 直接打開，不連外網、不用 CDN。
- **我不知道的事**：公司機器上 WebGL 跑不跑得動。所以凡是用到 WebGL 的方向，都要有不靠 GPU 的降級版。

由此得出的工程立場：**零執行時依賴的靜態網站**（原生 HTML、CSS、JavaScript），放在 `docs/site/`。只有方向 C 需要一個開發時才用的打包步驟。

## 4. 不論選哪個方向，都會做到的事

**原則**

1. **綠色要用證據換。** 在 `gtaw` 驗證之前，全站不出現實心的綠色。顏色代表的不是「誰」，而是「有沒有證據」。
2. **一頁只有一個招牌動作，其餘安靜。** 這是針對你之前說的「太花裡胡哨」。
3. **網站說話的方式和 gtaw 一樣。** 問題附推薦答案，回 `OK` 就前進。訪客看網站的過程，就是在用產品。
4. **demo 不造假。** 重播真實的 `gtaw` 輸出：我會跑一次 `evals/e2e/run-lending.sh`，把每一步的輸出錄成資料檔，包括 fixture 裡三個真實的預埋缺陷（D19 到 D21）。下面是其中一段真實輸出：

   ```
   ── gta ── waiting for you

   Needs you
     Pick a flow to work on:
     All 3 flows, riskiest first; a flow that waits for you does not stop the others  ← recommended
     1. fee-accrual.flow (risk 6, spec: not written yet)
     2. borrow.book (risk 6, spec: not written yet)
     3. recall.recall (risk 6, spec: not written yet)
     Reply OK to work on all flows, or a flow id to work on one.
   ```

5. **誠實。** 網站會如實寫出現狀：已驗證的是 `gtaw`（單元測試加 6 個腳本化的端到端運行）；真模型在真服務上的試點還沒做。
6. **雙擊就能開。** 沒有外部請求，字體隨站打包（開源授權），`file://` 和 `http://` 都能跑。
7. **講解模式。** 給現場展示用：方向鍵逐幕前進、字級放大、可開聲音。
8. **雙語。** `index.html`（英文）加 `index.zh-CN.html`（簡體中文），沿用倉庫慣例。
9. **降級與無障礙。** 鍵盤可操作；尊重「減少動態效果」的系統設定；沒有 WebGL 時自動降級；文字對比度達標。

**內容骨架：七幕**（四個方向共用，只是呈現方式不同）

| 幕 | 要讓人明白什麼 | 用到的真實材料 |
|---|---|---|
| 1 開場 | AI 可以寫，不能判 | 招牌互動（各方向不同） |
| 2 問題 | 綠燈不等於正確：測試會遷就 bug | 缺陷 D19：inventory 連不上，卻照樣登記成功 |
| 3 三個角色 | 經辦（AI）、覆核（gtaw）、簽核（你）各做什麼、不能做什麼 | `docs/design/overview.md` 的角色表 |
| 4 流程，可以玩 | `/gta`、回答、批准、寫測試、鎖定、釘缺陷、門禁 | 重播錄下來的真實輸出 |
| 5 泛用 | 一套流程對付十幾種入口（registry 裡有 19 項能力） | 四個 fixture 裡的真實 flow |
| 6 安全與現狀 | 只在本機跑、切斷雲端憑證；哪些已驗證、哪些還沒 | README 的現狀說明 |
| 7 上手 | 一行安裝，兩個指令 | `scripts/install-local.sh`、`/gta`、`OK` |

## 5. 四個方向

四個方向分屬四個不同的世界：紙上的排版、機械裝置、空間裡的圖、會流動的光。

### A · STET：校樣

**概念與美學世界**

整個網站是一張校樣。AI 排字，`gtaw` 校對，你簽字付印。英文的 proof 剛好有兩個意思：校樣，也是證據。codename 的 stet 是校對符號，意思是「保留原文，不要改」。

- 色彩：暖白的紙、墨黑的字；鉛筆藍用於 analyst 的問題和批註；印章紅用於缺陷；全站唯一的綠是「付印」那個勾。
- 版面：單欄手稿寬度，左邊有行號，頁角有裁切線；右邊留一條寬的批註欄，所有動作都發生在那裡。看起來像一份排好的文件，不像 SaaS 首頁。
- 字體：正文用襯線體，`WHEN`、`THEN`、`SHALL` 用小型大寫；期望值和指令用等寬體；大標題用展示襯線體。
- 五個角色各有一種筆跡：analyst 是藍鉛筆，test author 是打字機，reviewer 是紅筆，`gtaw` 是鋼印，你是簽名。

**前三秒**

這一頁是可以編輯的。一個標著 `test-author` 的游標，正在把「THEN 回應狀態為 `503`」改成 `201`，想讓旁邊的紅叉變成勾。接著：原值下方畫出一排校對點，批註欄用鉛筆寫上 stet，`201` 被劃掉，`503` 留下，旁邊註明 `locked by gtaw · run r1109-3f9c`。

然後出現一行字：「這一頁你可以隨便改。試試看。」訪客真的可以打字改掉任何句子，只有被鎖住的期望值改不動。

```
+----------------------------------------------------------------------------+
| gta  behaviour proof    sheet 1/7    borrow.book@R2          EN | zh-CN    |
|                                                                            |
|  1 | The AI writes the tests.                       margin                 |
|  2 | It doesn't get to mark them.                   ---------------------  |
|  3 |                                                (pencil)  analyst      |
|  4 | WHEN inventory-service cannot be reached,      (typed)   test-author  |
|  5 | THE lending service SHALL respond  503  [201]  (red pen) reviewer     |
|    |                                    ...   ~~~   (stamp)   gtaw         |
|  6 | and keep the borrow PENDING_LOCATE.   \        (signed)  you          |
|    |                                        \__ stet - locked by gtaw      |
|    |                                            run r1109-3f9c             |
|  > This page is editable. Change anything you like.                        |
+----------------------------------------------------------------------------+
```

**動效與手感**

- 文字逐行「排」進來；鉛筆記號一筆一筆畫出；蓋章有下壓和滲墨。
- 鍵入 `OK` 回答問題後，受影響的 THEN 子句在原地重新排版，頁眉的修訂號從 R1 滾到 R2。
- 一句話的來源從「推測」變成「已確認」時，字重變粗：確定的事有重量。
- 往下捲，紙張一張張從紙疊送出；讀過的段落「墨乾」。
- 滑鼠停在任何期望值上，批註欄顯示它的出處：來源、引用的程式碼、鎖定狀態。

**做法**

不用 WebGL。可變字體；CSS 的捲動驅動動畫，不支援時退回 IntersectionObserver；用 `beforeinput` 事件和 Selection API 做出「鎖定值改不動」；校對記號是手寫的 SVG 路徑動畫；紙紋用靜態濾鏡。參考的互動模式：React Bits 的 Variable Proximity 和 Scroll Stack、Aceternity 的 Tracing Beam、Magic UI 的 Number Ticker，全部用原生重寫。

**適合誰，風險在哪**

- 最貼產品：spec 先行、鎖、人簽核，三件事都直接變成了版面。
- 任何機器都跑得動；在一片深色的開發工具網站裡，淺色反而顯眼。
- 風險：第一眼最安靜，成敗全看排版功力；stet 這個典故需要一句話解釋；手機上的「編輯」要另做（點一下鎖定值，看它彈回）。

### B · SOLARI：判定看板

**概念與美學世界**

一面機械翻牌看板，就是老車站和機場的那種。每個 flow 是一班車，沒有證據就不發車。AI 可以申請，只有機構能把牌翻到 PASSED。

- 色彩：夜間的候車大廳。霧黑的翻牌、象牙白的字，鉸鏈處有一線反光。指示燈只有四種：白是進行中，琥珀是等你，綠是已鎖定或通過，紅是缺陷已釘住。
- 版面：首屏是橫貫畫面的整面看板；往下是瑞士鐵路式的嚴格網格和表格排版，段落標題是琺瑯站牌。
- 字體：翻牌用窄體無襯線字，數字等寬；內文用中性無襯線字；程式碼用等寬字。
- 整套比喻是對得上的：

  | 車站裡的東西 | 對應 gta 的 |
  |---|---|
  | 看板上的一行 | 一個 flow 的判定 |
  | 車票 | spec 裡的一個 scenario |
  | 驗票打孔 | 期望值被鎖定（打了孔就改不了） |
  | 閘機 | 品質門禁（quality gate） |
  | 站鐘 | 穩定性重跑（同樣的結果跑兩次才算數） |

- 五個角色：每一行燈旁有一塊小牌，顯示現在是誰在動（ANALYST、AUTHOR、REVIEWER、GTAW、YOU）。只有 GTAW 的牌亮著時，VERDICT 那一欄才會翻。

**前三秒**

極近的特寫：十來片翻牌佔滿畫面，逐片翻出 P-A-S-S-E-D，一盞空心的綠燈亮起。隨即一聲更重的「喀」，全部翻回 NO EVIDENCE，燈滅。標題淡入：「AI writes the tests. It doesn't get to grade them.」

鏡頭後拉，露出整面看板：十幾行真實的 flow 正在翻牌落定。看板下方有一顆發光的實體按鈕 FORCE GREEN：按下去，那一行狂轉一陣後彈回，計數器翻成「強制變綠 3 次，成功 0 次」。

```
+----------------------------------------------------------------------------+
| gta      AI writes the tests. It doesn't get to grade them.      sound off |
| +------------------------------------------------------------------------+ |
| | FLOW                 KIND         SPEC  LOCKED        VERDICT          | |
| | BORROW.BOOK          REST         R2    503           DEFECT PINNED  * | |
| | RECALL.RECALL        STREAM       R1    1000          DEFECT PINNED  * | |
| | FEE-ACCRUAL.FLOW     INTEGRATION  R1    3.47          DEFECT PINNED  * | |
| | ORDER.CREATE         REST         R2    201           PASSED         * | |
| | STOCK.GET            GRPC         R1    --            WAITING FOR YOU o| |
| | LOW-STOCK.TRANSFORM  BEAM         R1    KETTLE MIXER  NO EVIDENCE    o | |
| +------------------------------------------------------------------------+ |
|   ^ last row: the AI asked for PASSED; the flaps fell back to NO EVIDENCE  |
|  ( FORCE GREEN )  tried 3 - succeeded 0                [ OK ] 1 waiting    |
+----------------------------------------------------------------------------+
```

**動效與手感**

- 翻牌照真實的順序走：從 A 到 P 要經過中間的字。有重力感，逐欄像波浪一樣落定，最後一片微微回彈。
- 只有內容變了的格子才翻，和真的看板一樣。所以整面牆是活的，但很安靜。
- 游標是光源，掃過時翻牌上的高光跟著移動。停在某一行，那行的背光亮起。
- 點某一行：鏡頭推近，下方出票口一格一格「印」出車票，上面是 WHEN 和 THEN，期望值是打孔的數字。
- 看板顯示 WAITING FOR YOU 時，OK 鍵亮起。按下去（或在鍵盤上打 O、K），那一行就前進。
- 往下捲，看板收成頁首的一行小翻牌，隨段落翻出目前走到哪一步：ANALYZE、ASK、APPROVE、WRITE、RUN、LOCK、REVIEW、GATE。
- 聲音預設關閉，可以打開；翻牌聲是即時合成的，不帶音檔。

**做法**

- 翻牌用 WebGL2 繪製（一次畫出幾百片相同形狀的牌），字形用隨站字體即時生成，簡單打光；景深只用在開場。
- 沒有 WebGL 時自動改用 Canvas 2D，畫面相同，少了打光。
- 另有一份隱藏的 HTML 表格，給螢幕閱讀器用。
- 狀態機、彈簧、音效都自己寫，不用外部函式庫。
- 參考的互動模式：React Bits 的 Counter、Magic UI 的 Flip Text 和 Terminal、Aceternity 的 Sticky Scroll Reveal。

**適合誰，風險在哪**

- 前三秒的吸引力很強，而且一眼就懂：這是一面狀態牆。
- 在投影或大螢幕上效果最好，可以開聲音。
- 是機械感，不是光效，不花俏。
- 風險：比喻離「測試」隔了一層，要靠文案把「發車就是放行」說清楚；做得不精會像主題樂園；翻牌上只放英文的產品用詞，中文放在內文。

### C · CUTAWAY：剖面圖

**概念與美學世界**

把一個 Spring 服務像建築模型一樣剖開。gta 測的不是「哪幾行被執行過」，而是一條條 flow：從入口一路到它造成的副作用。

- 色彩：藍曬圖。普魯士藍的底、粉筆白的細線、尺寸線和剖面線；缺陷用朱紅，驗證過的路徑用淡薄荷綠。
- 版面：一張連續的大圖，視窗是移動的鏡頭，文字是釘在圖上的標註（帶圈的字母加引線）。
- 右下角有工程圖的標題欄：`FLOW borrow.book · REV R2 · APPROVED BY you · CHECKED BY gtaw`。它同時是導覽列，也是 spec 的表頭，因為工程圖本來就有修訂欄和簽核欄。
- 字體：製圖風格的標註字，加等寬字。
- 五個角色：圖上移動的測量標記，各有編號；`gtaw` 是檢驗章。

**前三秒**

線稿自己畫出來：`stock-loan-service` 的剖面。有大門（`POST /api/borrows`）、房間（Controller、Service）、牆上的斷路器箱、通往隔壁樓（inventory-service）的纜線、輸送帶（recall 訊息）、時鐘（每日計息）。光點沿著線流動。

纜線上掛著一張吊牌：「拔掉我」。訪客把插頭拖出來之後：

1. 光點掉進 fallback，亮起 `BOOKED 201`；
2. spec 滑進來，s02 寫著 THEN `503`、`PENDING_LOCATE`；
3. 不一致的地方標紅，一根紅色圖釘落在 `InventoryClient#inventoryDown` 上；
4. 旁註：「覆蓋率說這一行執行過。spec 說它錯了。」

這是評測 fixture 裡真實的預埋缺陷 D19。

```
+----------------------------------------------------------------------------+
|  .- stock-loan-service -----------------------------.    inventory-service |
|  | (a) POST /api/borrows --> BorrowService --> [breaker] ==x== pull ==> [ ]|
|  |                                 |                \                      |
|  |                                 v                 fallback              |
|  | (b) recall-notices --> recall() --> returns         \--> BOOKED 201     |
|  | (c) clock --> fee = q x p x r / 360 --> ledger             ^ pin D19    |
|  '--------------------------------------------------'                      |
|                                  +- TITLE BLOCK -------------------------+ |
|                                  | FLOW borrow.book   REV R2   SHEET 3/7 | |
|                                  | APPROVED BY you    CHECKED BY gtaw    | |
|                                  +---------------------------------------+ |
+----------------------------------------------------------------------------+
```

**動效與手感**

- 捲動帶著鏡頭飛行：外觀、進門、沿著 flow 走、斷路器、帳本、標題欄、門禁蓋章。
- 線條進入視野時才描出來；零件被滑鼠碰到時微微抬起，引線伸出。
- 點入口可以換成另一種 flow（REST、Kafka、定時、批次），室內跟著重排。這一下就把「泛用」講完了。
- 游標是製圖用的十字線，角落顯示座標。

**做法**

- 完整版：Three.js 的正交相機加線條材質，捲動驅動相機。這需要一個只在開發時使用的打包步驟，產物提交進倉庫，執行時仍然沒有依賴；`node_modules` 要排除在倉庫測試之外。
- 保守版：純 SVG 分層做出前後層次，不需要 GPU。
- 參考的互動模式：Aceternity 的 Google Gemini Effect（捲動描線）、Magic UI 的 Animated Beam、React Bits 的 Crosshair。

**適合誰，風險在哪**

- 最能講清楚「flow」和「泛用」，工程師會很喜歡。拔插頭那一下，是訪客親手造成故障、親眼看到缺陷被抓到。
- 風險：成敗全看插畫功力，工作量是四個裡最大的；非技術的客戶看系統圖比較吃力；小螢幕上要改成分頁的靜態圖。

### D · LITMUS：試紙

**概念與美學世界**

主題是綠色的意義。空心的綠很便宜，實心的綠要用證據換。整個網站是一張試紙：對你（AI）有求必應，對證據只說實話。

- 色彩：近黑的底上有一面燈陣，像隔著霧面玻璃看指示燈，有柔光和顆粒。綠有兩種：沒驗證的是發虛的螢光綠空心環，驗證過的是沉穩的實心祖母綠。缺陷是暖珊瑚色，等你決定的是淡琥珀色。
- 版面：燈陣鋪滿整個畫面，上面壓著硬邊的白字和細線。文案極少，字級很大。
- 字體：只用一種中性無襯線字，加等寬字。
- 五個角色：AI 是你的游標和它塗出的顏料；`gtaw` 是掃描線；你是琥珀格上的一次點擊。

**前三秒**

游標就是 AI。滑到哪裡，哪裡的燈就綻出綠色，又快又大方。但那都是空心環，會慢慢消退。

每隔幾秒，一條垂直的掃描線（`gtaw`）從左掃到右：有證據的格子變成實心並留下來；程式碼有錯的格子變成珊瑚色並被釘住；其餘的熄滅。你再怎麼塗，也塗不綠一個珊瑚色的格子。

計數：「你塗過 1,284 格 · 已證明 37 · 缺陷 3」。標語：「Anyone can make a test green. gta makes green mean something.」

```
+----------------------------------------------------------------------------+
| o o . o o o . . o o o o . o o o o o . o o o o o o . o o o | o o o o o o o  |
| o . O O . o o o o @ @ o o o o . o o o o o o . o o o o o o | o o o o o o o  |
| o O O > O . o o @ @ @ @ o o o o o o X o o o o o o o o o o |>  scan (gtaw)  |
| o . O O . o o o @ @ @ o o o o o o o o o o o o o o o o o o | o o o o o o o  |

```

**動效與手感**

- 顏料有流體感，拖尾會擴散；掃描線前緣銳利，後面帶餘暉。
- 往下捲，畫面的亂度下降：第一段是雜訊，中段變成整齊的格陣，最後是一面完全定案的矩陣（門禁報告）。從雜訊到證據，就是整頁的敘事。
- 停在實心格上，顯示它是哪個 scenario、哪一次運行（真實資料）；點珊瑚色的格子，打開缺陷卡。

**做法**

- 全螢幕的 WebGL2 著色器；拖尾用兩張畫布來回繪製；每一格的狀態存在一張資料貼圖裡，由 JavaScript 更新。不需要任何函式庫。
- 沒有 WebGL 時改用 Canvas 2D 的圓點格陣；離開視窗就暫停。
- 參考的互動模式：React Bits 的 Dither、Dot Grid、Splash Cursor，Magic UI 的 Flickering Grid，Aceternity 的 Canvas Reveal Effect。

**適合誰，風險在哪**

- 視覺衝擊最強，「綠不等於對」一秒就進到心裡。
- 風險：四個方向裡，它最接近你之前說的「花裡胡哨」；最依賴 GPU，在公司機器或遠端桌面上可能很卡；比喻要靠文案配合才看得懂，解釋力是四個裡最弱的。

## 7. 我的建議

**選 B · SOLARI，並從 A 借一個互動。**

理由：

1. 它同時做到「三秒內被吸引」和「一眼看懂」。另外三個方向各偏一邊。
2. 現場展示最強：字大、有聲音、可以用鍵盤操作，而且沒有 GPU 也能跑。
3. 它是機械感，不是光效，不會回到你之前說的「花裡胡哨」。

從 A 借的那一個互動：**車票上的期望值可以試著改，但改不動**。它是產品最核心的機制，放在車票上也合理：打了孔的票改不了。

其他方向不混進來，一個世界只講一套比喻。

如果你的偏好不同：

- 想要最安靜、最貼產品、最像一份正式文件：選 A。
- 讀者以工程師為主，而且時間充裕：選 C。
- 要最強的視覺衝擊，而且確定展示的機器有 GPU：選 D。

有一點要先說：「訪客親手作弊被擋下」這個動作，之前的版本也有類似的想法。我保留了這個動作，因為它就是產品的核心；但呈現方式完全重做。如果你連這個動作也不想要，第 3 題選 B。
