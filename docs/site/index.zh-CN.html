角色

四个 agent。各做一件事。

gtaw 不是第五个 agent。它是裁判：一个确定性的 Java 程序。同样的输入得到同样的判定，它不调用模型。

01 · 你说话的对象

gta-orchestrator

接收 /gta，向 gtaw 要下一个节点，再交给 analyst、author 或 reviewer。它展示 gtaw 的状态块。它不写规格，也不写测试，更不会替你回答。

next、check、submit、answer、note、status不能改文件不能 git，不能 mvn
02 · 读代码

gta-analyst

把一条流程写成行为规格：需求、场景、一张图，以及代码说不清的问题。它描述。它不判定今天的行为就是对的。

写指定的规格不能写 source=confirmed
03 · 写一条测试

gta-test-author

为一条已批准的场景写测试。期望值来自锁定的规格。规格和代码都定不下来怎么写时，author 会问，而不是猜。

只能改 brief 里的测试文件不能动 src/main不能 @Disabled
04 · 判断，但不改

gta-reviewer

对照已批准的场景读测试，返回一个判定。它从不会建议把期望值改成代码实际返回的值。

测试在这台机器上跑
gtaw 和测试在你这台机器上运行。模型请求，以及这些数据如何被处理，取决于 GitHub Copilot 或 OpenCode，以及你使用的提供方。每次测试运行都会去掉云凭证，以及 shell 里的 Spring profile 和配置变量。SIT、UAT 和生产环境都不在范围内。agent 的规则只允许本地依赖。Kafka 和 JMS 以内嵌方式运行。BigQuery 和 GCS 用替身。Oracle 用 H2 的 Oracle 模式或共享测试库。Pub/Sub 用内存替身或模拟器。

          
它会问。它不猜。
一个 OK 接受推荐。OK, 2B 改掉其中一个选项。好和确认都算 OK。批准 order.create@R2 批准该修订。其余默认保留其余问题今天的行为；这些场景会变成特征测试。它们锁定代码现在的做法，并不证明这样做是对的。

          
已知缺陷保持可见
因为代码写错而失败的测试可以用 @KnownDefect 标住。缺陷还在时，构建保持绿灯。代码修好之后，测试会变红，直到去掉这枚钉子。覆盖率只作参考。

          
版本
Spring Boot 2.2 到 4.1。服务可以是 Java 8 及以上。Maven 或 Gradle，单模块或多模块，Windows、macOS 和 Linux 都可以。gtaw 本身需要 JDK 17 或更新。不需要另外的模型密钥：agent 用 Copilot 或 OpenCode 已经提供的模型。模型请求以及这些数据如何被处理，取决于那个产品和你使用的提供方。gtaw 不调用模型，也不需要 Docker。
