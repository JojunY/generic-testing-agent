角色

四个 agent。gtaw 是裁判。

gtaw 不调用模型。

01 · 你说话的对象

gta-orchestrator

它接收 /gta，再问 gtaw 下一步。

02 · 读代码

gta-analyst

它为一个流程写候选规格。

03 · 写一条测试

gta-test-author

它按锁定的规格写一条测试。

04 · 只作判断

gta-reviewer

它给出一个结论，并且不修改测试。

他们不能做的事

orchestrator 不改文件，不替你回答，也不运行 git 或 mvn。

analyst 不能把来源写成 confirmed。

author 不改 src/main，也不加 @Disabled。

reviewer 只读。

 仓库里实际有的

          
这些数字来自本仓库。

          

            
4具名 agent，各做一件事

            
4一条场景可以要求的层级

            
1被允许判定通过的程序

            
20core/skills 里的技能

          

          

            这些数字指什么
            
层级是 unit、slice、component 和 contract。gtaw 不安排 system。

            
20 是 core/skills 里的目录数。单元和 slice 的变异测试默认只作建议，除非项目自己打开。

          

          

            测试在哪里跑
            
gtaw 和测试在你这台机器上运行。模型请求取决于 Copilot 或 OpenCode，以及你使用的提供方。

            
每次测试去掉云凭证和 Spring profile。Kafka 和 JMS 以内嵌方式运行。BigQuery、GCS、Oracle 和 Pub/Sub 使用替身或共享测试库。

          

          

            版本
            
Spring Boot 2.2 到 4.1。服务可以是 Java 8 或更新版本。gtaw 需要 JDK 17 或更新版本。
