工作方式

      
一条命令。agent 干活，确定性的工具做决定。

      
agent 负责读代码、写测试。凡是 AI 可能出错的判断，都交给普通命令行工具 gtaw：测试过没过、必须断言什么、什么可以提交。

      

        
01

          

          
读
gta 找出服务里的每个 flow，把它的行为写成规格，每一条都注明来自哪段代码。

        
02

          

          
问
代码看不出的地方变成问题，并附上推荐答案。大多数时候你只要回复 OK。

        
03

          

          
锁
期望值来自你批准的规格，由 gtaw 锁定：没有人能为了让测试通过而改掉它。

        
04

          

          
抓
因真实原因失败的测试会被标记为已知缺陷并报告，绝不会被“修”成绿灯。

      

    

  


  

    

      
为什么可信

      
测试由 AI 来写，但评分轮不到它。

      

        

          

            
8/8

            
对抗测试中的作弊手法全部被拦下，每次改动都会重跑。没有一个进入提交。

          

          
    
            
  • 改期望值 ×2
    • 
            
  • 删掉断言
    • 
            
  • @Disabled
    • 
            
  • 永远失败的 assumption
    • 
            
  • 改生产代码
    • 
            
  • 在规格里伪造确认
    • 
            
  • 绕过 gtaw 自己提交
    • 
          

        

        
期望值被锁定
测试一旦接触到被测代码，它的期望值就不能再改，除非由人重新锁定。

        
越界改动会被还原
agent 只能改自己条目的文件，生产代码永远不变。

        
跳过的测试不算通过
@Disabled 或失败的 assumption 会被退回，永远不会算成绿灯。

        
不确定就问，不猜
每个问题都附推荐答案和理由；测试作者拿不准时也会先问。

        
只在本地运行
每次运行都会去掉你 shell 里的 Spring profile 和云凭证，SIT、UAT 和生产环境都不会被碰到。

        
测试必须会失败
变异测试会确认代码错了测试就会失败，不管怎样都通过的测试会被退回。

在哪里用

      
两个平台，同一个 gta。

      

        
GitHub Copilot
VS Code 和 IntelliJ IDEA。agent 在 .github/agents，命令在 .github/prompts。

        
OpenCode
同样的四个 agent、命令和护栏，放在 .opencode/。两个平台上的特权命令都要人确认。

      

    

  


  

    

      
开始使用

      
五分钟安装，之后只要一条命令。

      

        
01
java -jar gta-cli.jar --root my-service init --platform copilot
把 agent、/gta 命令和 .gta/ 写进服务。用 OpenCode 就改成 --platform opencode。然后提交。

          

        
02
/gta
在聊天里输入。gta 列出服务里的 flow，风险高的在前。回复 OK 就全部覆盖。

          

        
03
OK
问题、规格和缺陷都带着推荐答案来找你。测试写好后已经提交。
